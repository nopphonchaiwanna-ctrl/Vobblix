# 3D Shop Lobby Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Phaser 2D shop floor with a Three.js 3D card shop (cute characters, tables, a counter, an events board), a C1 "seated at table" video layout, a game-style HUD, and a landscape mobile mode.

**Architecture:** The server stays the source of truth for layout, presence, and chat. It gains counter/board/spawn positions, a join-table range check, and a persisted `avatar_config`. The client swaps `scenes/ShopScene.js` (Phaser) for a `scene3d/` module. `ShopWorld` owns the renderer and the socket presence. Pure logic (movement, proximity, joystick, big-screen choice, character resolve) lives in small DOM-free modules that are unit-tested with `node --test`. Everything else stays as DOM layered over the canvas, re-arranged by `body` state classes (`in-shop`, `seated`).

**Tech Stack:** three (r16x, ES modules: GLTFLoader, SkeletonUtils, CSS2DRenderer), Vite 5, vanilla JS, Socket.io, Express + raw `pg`, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-21-3d-lobby-design.md` (Thai). Read it before starting any task.

## Global Constraints

- Never use any art, model, image, or sound from Shadowverse / Cygames. Only **CC0** assets (Kenney, Quaternius, KayKit). Every file is listed in `client/public/models/CREDITS.md`.
- Name is **VobbLiX** only. Don't invent a logo.
- Server source of truth; floor coordinates stay in floor pixels server-side. Client mapping: `1 floor px = 0.01 world units`.
- Keep existing limits/behaviour: voice ≤10, video ≤4 per table; move emit every 50 ms; `PLAYER_SPEED = 220` px/s; `PLAYER_RADIUS = 16`; `TABLE_SOLID_RADIUS = 46`; `REMOTE_LERP = 0.25`.
- New UI copy is English (the app has no i18n yet). Put every new string in `client/src/scene3d/strings.js` so i18n can pick them up later. Fonts must render Thai.
- Respect `prefers-reduced-motion`: instant camera cuts, no animated transitions.
- Use `confirmDialog()` / `<dialog>`, never `window.confirm/prompt`.
- Never edit a migration that already ran; new migration is `019_*`.
- Don't assume Vanguard is the only game.
- Performance target: ≥30 fps on a mid-range Android with 30 players in the shop; 60 fps desktop. Pixel ratio capped at `1.5` on coarse pointers, `2` otherwise. No real-time shadow maps.
- Verification before "done": `cd server && npm run test:all` for server changes; `cd client && npm test && npm run build` and `node --check` on touched JS for client changes.
- The user approved one commit per task on branch `dev` for this run (2026-10-21). Don't push.

## Review Focus

1. **Opening an overlay while in a call:** opening Settings / Decks / Events / Orders from the ⊞ menu while seated must not end the call or freeze video. Closing it should land you back seated, with the call still live. (Manual check in Task 9.)
2. **Leaving and re-entering a shop repeatedly** (lobby → shop → lobby → shop, also mid camera transition): the renderer, the animation-frame loop, and the socket listeners must be disposed. Re-entering must not double them up, which would show as doubled chat lines or doubled "player-moved" handling. (Task 6 step + manual check.)
3. **A model fails to load or WebGL is unavailable:** a missing or 404 `.glb` falls back to a placeholder capsule, and no WebGL shows a readable message. Chat and the call must still work. Neither case should leave a blank screen. (Task 5 test for the fallback choice, Task 6 manual check.)
4. **On a phone, rotating mid-session or opening the soft keyboard:** the renderer resizes. The joystick releases on `touchcancel` and doesn't keep walking. The rotate overlay never tears down the call. (Task 10.)
5. **Players already present when you join:** they appear at their position with their table ring (`tableId` set). An unknown or invalid `avatarConfig.character` renders the default character instead of crashing. (Task 5 test `resolveCharacter`, Task 6.)

  1. `pinnedId` if it's still present
  2. the first non-local tile with `videoOn`
  3. the local tile if `videoOn`
  4. the first non-local tile
  5. `null`
