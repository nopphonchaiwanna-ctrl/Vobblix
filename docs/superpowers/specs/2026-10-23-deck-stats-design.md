# อีเวนต์ ส่วนที่ 4: ส่งเด็ค + สถิติเกรด 3 ในไรด์ไลน์ — เอกสารออกแบบ

วันที่: 2026-10-23 · สถานะ: ผ่านผู้ตรวจแล้ว รอผู้ใช้อนุมัติ

"(ผู้ใช้)" = ผู้ใช้ตัดสินเอง · "(Claude)" = Claude ตัดสินแทน ผู้ใช้ค้านได้

## 1. เจตนา

เจ้าของร้านและ admin อยากรู้ว่า **ในงานแวนการ์ด ผู้เล่นไรด์เกรด 3 อะไรกัน และเกรด 3 ไหนชนะบ่อย**
ผู้เล่นเองก็อยากเห็นในประวัติการแข่ง (ส่วนที่ 3) ว่าแต่ละรอบคู่แข่งใช้เกรด 3 อะไร (ผู้ใช้)

เพื่อให้ได้ข้อมูลนี้ ผู้เล่นต้องส่งเด็คเข้างาน และระบบอ่านเกรด 3 จาก Ride Deck เอง
ไม่ให้พิมพ์ชื่อเอง เพราะชื่อที่สะกดต่างกันจะทำให้สถิติแตกเป็นหลายกลุ่ม (ผู้ใช้กังวลเรื่องนี้)

### ทำไมไม่มีฟอร์แมต TH
ฟอร์แมต TH ไม่มี Deck Log ร้านไทยตอนนี้ก็ยังไม่มีวิธีเก็บข้อมูลเด็ค แอป KK card fight ที่ผู้เล่นไทยใช้แชร์เด็คได้แค่เป็นรูป
และคลังการ์ดของเรามีแต่การ์ดญี่ปุ่น ขาดการ์ดที่ออกเฉพาะในไทย
ผู้ใช้จึงตัดสินว่า **ฟอร์แมต TH ไม่ต้องส่งเด็คและไม่ทำสถิติ** (ผู้ใช้)

## 2. เป้าหมาย

1. ใช้กับงานแวนการ์ด **JP + D Standard** เท่านั้น (ผู้ใช้)
2. ตอนสร้างหรือแก้งาน ผู้จัดเลือกว่า **ไม่ต้องส่งเด็ค / ส่งได้แต่ไม่บังคับ / บังคับส่ง** (ผู้ใช้ให้ผู้จัดเลือกบังคับหรือไม่บังคับ; ตัวเลือก "ไม่ต้องส่ง" = Claude เพื่อให้งานที่ไม่สนใจสถิติไม่ต้องยุ่ง)
3. ผู้เล่นส่งเด็คด้วยโค้ดหรือลิงก์ Deck Log หรือเลือกจาก My deck ระบบเก็บสำเนาของงานนั้นไว้แยก และอ่านเกรด 3 จาก Ride Deck เอง
4. ใครเห็นอะไร (ผู้ใช้ยืนยันแล้ว):
   - ผู้จัดและกรรมการเห็นเด็คเต็มของทุกคนได้ตลอด
   - ผู้เล่นเห็นแค่เด็คของตัวเอง
   - หลังงานจบ ประวัติการแข่งของผู้เล่นแสดงเกรด 3 ของคู่แข่งในแต่ละรอบ ไม่แสดงเด็คเต็ม
5. **สถิติต่องาน** ให้เจ้าของร้านดูหลังงานจบ แต่ละแถวคือเกรด 3 หนึ่งใบ บอกจำนวนคนที่ใช้, สัดส่วน, **% ชนะ** และผลดีที่สุด (ผู้ใช้: % ชนะ; ผลดีที่สุด = Claude ผู้ใช้เห็นด้วย)
6. **สถิติรวมทุกงาน** ให้ **admin เท่านั้น** ดู และ **เลือกช่วงเวลาได้** (ผู้ใช้)

## 3. ไม่อยู่ในขอบเขต

- ฟอร์แมต TH ทุกแบบ และงาน Premium (ผู้ใช้)
- การพิมพ์ชื่อเกรด 3 เอง และการเพิ่มการ์ดที่ออกเฉพาะในไทยเข้าคลัง (ผู้ใช้: ไม่ทำสถิติ TH)
- ดึงข้อมูลจากแอป KK card fight (แชร์ได้แค่เป็นรูป)
- ตรวจว่าเด็คถูกกติกาเต็มรูปแบบ (เช่นจำนวน 50 ใบ หรือการ์ดต้องห้าม) ระบบตรวจแค่สิ่งที่สถิติต้องใช้ (§5.3) (Claude)
- ตารางว่าเกรด 3 ไหนชนะเกรด 3 ไหน (matchup) (Claude: ผู้ใช้ไม่ได้ขอ)
- ผู้เล่นเห็นเด็คเต็มของคู่แข่ง (ผู้ใช้)

## 4. ตั้งค่าในงาน

- คอลัมน์ใหม่ `tournament_events.deck_submission`: `'off' | 'optional' | 'required'` ค่าเริ่มต้น `'off'`
- ตั้งได้เฉพาะงานที่ `game = 'vanguard'`, `vanguard_region = 'jp'` และ `vanguard_regulation = 'd_standard'` งานอื่น server บังคับให้เป็น `'off'` เสมอ
- แก้ได้ **ตอนเปิดรับสมัครเท่านั้น** เหมือนช่อง game/region/regulation ที่ล็อกตั้งแต่เปิดรายงานตัว (`updateEventCheckInBasics` รับแค่ชื่อ เวลาเริ่ม และเวลาต่อรอบ) จึงไม่ต้องทำข้อยกเว้นให้ช่วงรายงานตัว (Claude หลังผู้ตรวจชี้)
  - `PATCH` ตอนรับสมัครส่ง settings ครบทุกช่อง ถ้าไม่มี `deckSubmission` ให้คงค่าเดิมไว้ (Claude)
  - ถ้าเปลี่ยนงานจาก JP D Standard เป็นอย่างอื่นตอนรับสมัคร ค่าจะกลับเป็น `'off'` เด็คที่ส่งมาแล้วยังเก็บไว้ แต่ไม่แสดงและไม่นับ (Claude)
- ฟอร์มสร้าง/แก้งาน (`eventForm.js`): ช่อง "Deck submission" (Off / Optional / Required) แสดงเฉพาะเมื่อเลือก JP + D Standard

## 5. ส่งเด็ค

### 5.1 ข้อมูล (migration ใหม่ 023)

- `event_decks`: `id`, `event_id`, `player_id` (unique ต่อ player), `decklog_code`, `source_locale`, `title`, `nation`, `submitted_at`, `updated_at`
- `event_deck_cards`: เหมือน `deck_cards` (`card_number`, `decklog_card_number`, `zone`, `quantity`) ผูกกับ `event_deck_id`
- เป็น **สำเนา** ของเด็คตอนส่ง ถ้าผู้เล่นไปแก้หรือลบ My deck ทีหลัง สำเนานี้ไม่เปลี่ยน (Claude)
- ไม่ต้องเก็บชื่อเกรด 3 ไว้ในตาราง ให้คำนวณจาก `zone = 'ride'` join `cards` ตอนอ่าน การ์ดที่เพิ่งนำเข้าคลังทีหลังจะได้แสดงชื่อเองโดยไม่ต้อง backfill (Claude)

### 5.2 การส่ง
- `PUT /events/:id/deck` รับ `{ deckId }` (เลือกจาก My deck ของตัวเอง) หรือ `{ code, sourceLocale }` (โค้ด Deck Log ใหม่)
  - server รับแค่โค้ดเปล่าเหมือน `POST /decks/import` การแยกโค้ดและ locale ออกจากลิงก์ทำที่ client ด้วย `parseDecklogInput` ซึ่งตอนนี้อยู่ใน `decksPanel.js` ให้ย้ายไปเป็นโมดูลกลางที่ทั้งสองหน้าใช้ร่วมกัน (Claude หลังผู้ตรวจชี้)
  - ถ้าเป็นโค้ดใหม่ ใช้ `fetchDecklogDeck` แล้ว **บันทึกเข้า My deck ด้วย** (Claude) จากนั้นคัดลอกเป็นสำเนาของงาน
  - ส่งซ้ำ = แทนที่ของเดิม
- `DELETE /events/:id/deck` ถอนเด็คที่ส่งไว้ ทำได้เฉพาะงานที่ไม่บังคับ (Claude)
- ส่ง แทนที่ หรือถอนได้ตอน `registration` และ `check_in` เท่านั้น พองานเริ่ม (`swiss` ขึ้นไป) **เด็คล็อก** (ผู้ใช้ยืนยันตอน play back)
- คนส่งได้คือคนที่มีแถวในงานและยังไม่ drop รวมถึงคนใน waitlist และคนที่รอ lottery (Claude: ให้เตรียมไว้ก่อน)
- ส่งได้เฉพาะงานที่ `deck_submission` ไม่ใช่ `'off'`

### 5.3 สิ่งที่ระบบตรวจ (ไม่ผ่าน → 400 พร้อมข้อความชัดเจน)
- **Ride Deck ว่าง** → 400 "This deck has no ride deck - submit a D Standard deck." นี่เป็นกรณีเดียวที่ปฏิเสธ
- Ride Deck มีการ์ด แต่หาเกรด 3 ในคลังไม่เจอ (เช่นเกรด 3 จากชุดใหม่ที่ยังไม่ได้นำเข้าคลัง) → **รับไว้** แล้วจัดเป็น "Unknown" (Claude)
  - ไม่ปิดทางผู้เล่นเพราะคลังของเราล้าหลัง และเกรด 3 คำนวณตอนอ่าน (§5.1) พอนำเข้าการ์ดชุดใหม่แล้ว Unknown จะกลายเป็นชื่อจริงเอง ทั้งในสถิติและในประวัติ
- ไม่ตรวจว่าเป็น D Standard จริงหรือไม่ เพราะ Deck Log ไม่ได้บอกฟอร์แมตชัด ๆ ข้อจำกัดนี้ยอมรับได้ (Claude)

### 5.4 บังคับส่ง
เมื่อ `deck_submission = 'required'`:
- `POST /:id/check-in` (ผู้เล่นขอรายงานตัว) → 409 "Submit your deck before checking in." ถ้ายังไม่ส่ง
- `POST /:id/check-in/approve` ตรวจเองด้วย (approve รายคนไม่ต้องมีคำขอรายงานตัวก่อน) ยังไม่ส่ง → 409 "This player hasn't submitted a deck."
- `POST /:id/check-in/auto` ตอนนี้เป็น bulk UPDATE เดียวที่คืนแค่จำนวน (`approveCheckInForUsers`) ต้องแก้ให้ข้ามคนที่ยังไม่ส่งเด็คเมื่อบังคับส่ง และคืน `{ approved, skippedNoDeck: [displayName…] }` toast ฝั่ง client บอกว่าใครถูกข้าม (Claude)
- `POST /:id/start` ไม่ต้องเช็กซ้ำ เพราะผ่านด่าน approve มาแล้ว

## 6. ใครเห็นอะไร

- `GET /events/:id` เพิ่มข้อมูล:
  - ผู้เล่น: `myDeck` = เด็คของตัวเอง (ชื่อ, โค้ด, เกรด 3, รายการการ์ด) หรือ null
  - staff (ผู้จัด/กรรมการ): ทุก player มี `deckSubmitted: boolean` และเกรด 3 สั้น ๆ
- `GET /events/:id/decks/:playerId` staff เท่านั้น: เด็คเต็มของผู้เล่นคนนั้น แสดงด้วยหน้าตาเดียวกับหน้ารายละเอียดใน My deck
- ผู้เล่นไม่เห็นเด็คหรือเกรด 3 ของคนอื่นผ่าน API ใด ๆ ระหว่างงาน
- หลังงานจบ `GET /events/history` เติม `opponentDeck` ของแต่ละแมตช์ (ช่องจากส่วนที่ 3):
  `{ g3: [{ name, cardNumber, imageUrl }] }` หรือ null ถ้าคู่แข่งไม่ได้ส่ง / งานไม่ได้เปิดส่งเด็ค / เป็นบาย
  - หน้า Match history ตอนนี้แค่เว้นช่องไว้และ render เป็นข้อความ (`escapeHtml(m.opponentDeck ?? "")`) ต้องเขียน render ใหม่ให้แสดงรูปเล็ก + ชื่อของเกรด 3 แต่ละใบ พร้อม CSS (คอลัมน์ยังโผล่เฉพาะเมื่อมีค่า)

## 7. สถิติ

### 7.1 กลุ่มเกรด 3 (ใช้ทั้งต่องานและรวม)
- กลุ่ม = **ชื่อการ์ด** (`cards.name`) ของเกรด 3 ใน Ride Deck การ์ดพิมพ์ซ้ำหลายชุดแต่ชื่อเดียวกันนับเป็นกลุ่มเดียว (Claude)
- ถ้า Ride Deck มีเกรด 3 หลายชื่อ ให้กลุ่มเป็นชื่อเรียงตามตัวอักษรต่อกันด้วย " / " (Claude)
- รูปที่แสดงใช้รูปของ card_number ที่พบบ่อยสุดในกลุ่ม (Claude)
- เนชั่นใช้ `cards.nation` ของการ์ดนั้น (ค่าญี่ปุ่น ตามที่ระบบใช้อยู่)
- เด็คที่หาเกรด 3 ในคลังไม่เจอ → กลุ่ม "Unknown" แถวนี้แสดงแค่ Players กับ Share ไม่แสดง Win % (ขึ้น "—") เพราะ Unknown อาจเป็นหลายเด็คปนกัน แมตช์ที่ Unknown เจอ Unknown ก็ไม่นับเป็น "กลุ่มเดียวกัน" (Claude)

### 7.2 ตัวเลขแต่ละแถว
| คอลัมน์ | นิยาม |
|---|---|
| Players | จำนวนผู้เล่นที่ลงแข่งจริง (นิยามเดียวกับส่วนที่ 3: entered, ไม่ no-show, มีแมตช์อย่างน้อยหนึ่ง) และส่งเด็คในกลุ่มนี้; แบบรวมทุกงานนับเป็น **จำนวนครั้งที่ลงแข่ง** คนเดียวลง 5 งานนับ 5 แบบเดียวกับสถิติ metagame ทั่วไป (Claude) |
| Share | Players ÷ จำนวนผู้เล่นที่ลงแข่งจริงและส่งเด็ค |
| Win % | (ชนะ + 0.5 × เสมอ) ÷ แมตช์ที่นับ; นับแมตช์ทั้ง Swiss และ top cut ที่มีผลแล้ว **ไม่นับบาย** และ **ไม่นับแมตช์ที่ทั้งสองฝั่งอยู่กลุ่มเดียวกัน**; แมตช์ที่คู่แข่งไม่ได้ส่งเด็คยังนับ (ผลของฝั่งเรายังมีความหมาย); แพ้ทั้งคู่นับเป็นแพ้ (Claude ผู้ใช้เห็นด้วยตอน play back) |
| Matches | จำนวนแมตช์ที่นับใน Win % (ให้ดูว่าตัวเลขมีน้ำหนักแค่ไหน) |
| Best finish | ต่องาน: ผลดีที่สุดในกลุ่ม ใช้ป้าย `PLACEMENT_LABELS` ถ้ามี `final_label` ไม่มีก็ `#rank`; รวมทุกงาน: **"1st ×N · Top cut ×M"** โดยนับอันดับ 1 จาก `final_rank = 1` (รวมแชมป์ของงาน Swiss-only ที่ไม่มี label) และนับ Top cut จากคนที่มี `final_label` (Claude หลังผู้ตรวจชี้) |

- เรียงตาม Players มากไปน้อย ถ้าเท่ากันเรียงตาม Win % มากไปน้อย
- ใต้ตารางบอกว่า "N players didn't submit a deck" (ผู้ใช้ยืนยันตอน play back)
- Win % คำนวณในฟังก์ชันบริสุทธิ์ `server/src/tournament/deckStats.js` แล้ว unit test

### 7.3 ต่องาน — เจ้าของร้าน
- `GET /events/:id/deck-stats` เจ้าของร้านหรือ admin; กรรมการไม่ได้ (Claude: ผู้ใช้บอกว่า "เจ้าของร้าน") ได้เฉพาะเมื่อ `status = 'completed'` และงานเปิดส่งเด็ค ไม่อย่างนั้น 409 หรือ 404
- หน้าผู้จัด (`organizerView.js`) ของงานที่จบแล้วมีส่วน "Deck stats"

### 7.4 รวมทุกงาน — admin เท่านั้น
- `GET /admin/deck-stats?from=YYYY-MM-DD&to=YYYY-MM-DD` admin เท่านั้น รวมทุกงาน JP D Standard ที่ `completed` และเปิดส่งเด็ค โดยดู `completed_at` ว่าอยู่ในช่วงเวลาที่เลือกหรือไม่
  - วันตีความเป็นเวลา `Asia/Bangkok` (เหมือน schedule.js ของส่วนที่ 2) `to` นับรวมทั้งวัน ไม่ใส่ = ไม่จำกัด
- หน้า admin มีหัวข้อใหม่ "Deck stats" ใน sidebar มีตัวเลือกช่วงเวลา: "Last 30 days" / "Last 90 days" / "All time" / กำหนดเอง (วันเริ่ม–วันจบ) (ผู้ใช้: เลือกช่วงเวลาได้; ตัวเลือกสำเร็จรูป = Claude)
- ใต้ตารางบอกจำนวนงานและผู้เล่นที่รวมอยู่

## 8. หน้าผู้เล่น (`playerView.js`)

ในงานที่เปิดส่งเด็ค ก่อนงานเริ่ม:
- กล่อง "Your deck" บอกสถานะ: ยังไม่ส่ง (ถ้าบังคับให้ขึ้นว่า "Required before check-in") หรือส่งแล้ว (ชื่อเด็ค + เกรด 3 + รูป)
- ปุ่ม "Submit deck" / "Change deck" เปิด `<dialog>` ให้เลือกจาก My deck หรือวางลิงก์/โค้ด Deck Log ใหม่ พร้อมตัวเลือก locale (ตรวจ locale จากลิงก์ให้เอง เหมือน My deck)
- ถ้างานไม่บังคับ มีปุ่ม "Withdraw deck"
- หลังงานเริ่ม กล่องนี้แสดงเด็คที่ส่งไว้แบบอ่านอย่างเดียว

หน้าผู้จัดตอนรายงานตัว: แต่ละคนมีป้าย "Deck ✓" หรือ "No deck" ถ้าบังคับส่ง ปุ่ม approve ของคนที่ยังไม่ส่งจะกดไม่ได้ กดดูเด็คเต็มได้ (§6)

## 9. เทสต์และการตรวจ

- Unit: `deckStats.js` — จัดกลุ่มตามชื่อ, หลาย G3, Unknown, Win % (บาย, เสมอ, แพ้ทั้งคู่, กลุ่มเดียวกัน, คู่แข่งไม่ส่งยังนับ), Best finish
- Integration (ใช้ `fetchDecklogDeck` ปลอมหรือ `{ deckId }` จาก deck ที่ seed ไว้ ห้ามยิง Deck Log จริงในเทสต์):
  - ตั้ง `deck_submission` ในงานที่ไม่ใช่ JP D Standard → ถูกบังคับเป็น `off`
  - ส่ง / แทนที่ / ถอนเด็ค; หลังงานเริ่มทำไม่ได้; แก้ My deck แล้วสำเนาในงานไม่เปลี่ยน
  - บังคับส่ง: check-in, approve และ auto ปฏิบัติตาม §5.4
  - การมองเห็น: ผู้เล่นไม่เห็นเด็คหรือเกรด 3 ของคนอื่นทั้งระหว่างงานและหลังงาน ยกเว้นผ่าน `opponentDeck` ในประวัติหลังงานจบ; กรรมการเห็นเด็คเต็ม
  - deck-stats ต่องาน: สิทธิ์ (เจ้าของร้าน ✓, กรรมการ ✗, ผู้เล่น ✗) และตัวเลขถูกต้องในงานที่ seed ไว้
  - admin deck-stats: สิทธิ์ (admin เท่านั้น) และช่วงเวลา Bangkok
  - ประวัติ: `opponentDeck` ถูกเติมเมื่อคู่แข่งส่งเด็ค และเป็น null เมื่อไม่ส่ง
- `npm run test:all`, client `npm test` + `npm run build`, คลิกทดสอบจริงกับ test DB

## 10. เรื่องที่ปล่อยให้ builder ตัดสิน

- ชื่อตาราง คอลัมน์ ฟิลด์ และฟังก์ชัน
- หน้าตาตารางสถิติและ dialog ส่งเด็ค (ใช้ pattern ที่มีอยู่ เช่น `<dialog>` และ `.dashboard-shell`)
- จะใช้ฟังก์ชันแสดงรายการการ์ดของ My deck ร่วมกัน หรือแยกออกมาเป็นโมดูลใหม่
