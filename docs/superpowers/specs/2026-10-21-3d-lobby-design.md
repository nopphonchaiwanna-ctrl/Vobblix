# ล็อบบี้ร้าน 3D — เอกสารออกแบบ

วันที่: 2026-10-21 · สถานะ: ผ่านการตรวจแล้ว รอผู้ใช้อนุมัติ

ในเอกสารนี้ "(ผู้ใช้)" = ผู้ใช้ตัดสินใจเอง, "(Claude)" = Claude ตัดสินใจแทน ผู้ใช้ยังค้านได้

## 1. เจตนาและเหตุผล

ผู้เล่นที่เข้ามาใน VobbLiX ควรรู้สึกว่า **"กำลังเดินอยู่ในร้านการ์ดจริงๆ"** ล็อบบี้ 2D ตอนนี้
(`client/src/scenes/ShopScene.js`, Phaser 3) มีแค่สี่เหลี่ยมโต๊ะบนพื้นตาราง ตัวละครเป็นวงกลมสี
จึงไม่ได้ฟีลร้านการ์ดเลย (ผู้ใช้)

ปัญหาที่ผู้ใช้เจอจริงกับของเดิม
- แชทร้าน แชทโต๊ะ และ voice/video call อัดกันอยู่ในแถบขวาหน้าเดียว ใช้งานยาก (ผู้ใช้)
- บนมือถือใช้งานไม่ได้จริง: ไม่มีปุ่มให้เดิน ฉากร้านถูกตัดขอบ แผงแชทเบียดจนแคบ (ผู้ใช้ ส่ง screenshot มาให้ดู)

แรงบันดาลใจคือ**ฟีล**ของ lobby ใน *Shadowverse: Worlds Beyond* โดยเฉพาะ**ตัวละคร 3D น่ารักๆ**ที่เดินไปมาในพื้นที่เดียวกัน (ผู้ใช้)

ผู้ใช้ตั้งใจให้ทำออกมาก่อนแล้วค่อยปรับ ("ลองทำมาก่อนแล้วมาแก้กันอีกที") งานรอบแรกจึงต้อง**เล่นได้จริงครบลูป**
มากกว่าจะเนี้ยบทุกมุม

## 2. เป้าหมาย

1. แทนที่ฉากร้าน 2D ด้วยฉาก 3D (แทนที่เลย ไม่เก็บโหมด 2D ไว้คู่กัน) (ผู้ใช้: "เปลี่ยนจาก 2D เป็น 3D ไปเลย")
2. ในร้านมีของที่ทำให้รู้สึกว่าเป็นร้านการ์ด (ผู้ใช้):
   - **โต๊ะ**ให้นั่งเล่น เดินเข้าใกล้โต๊ะแล้วเข้าแชทโต๊ะและ voice/video ของโต๊ะนั้น เหมือนเดิม
   - **เคาน์เตอร์ขายของ** เดินไปที่เคาน์เตอร์แล้วเปิดรายการสินค้าของร้าน (ระบบ listings/orders เดิม)
   - **บอร์ดประกาศข่าวสารและอีเวนต์** เดินไปที่บอร์ดแล้วเปิดรายการอีเวนต์ของร้าน (ระบบ events เดิม)
   - ทั้งเคาน์เตอร์และบอร์ด**มีปุ่มบน HUD ให้กดเปิดได้เลย**โดยไม่ต้องเดินไป (ผู้ใช้)
3. ตัวละคร 3D น่ารัก (สัดส่วนจิ๋ว หัวโต) เดินไปมา เห็นผู้เล่นคนอื่นเคลื่อนที่แบบเรียลไทม์ (ผู้ใช้)
4. แก้ปัญหา UI อัดกันด้วย **โหมดนั่งโต๊ะ** (§5) และ **HUD แบบเกม** (§6)
5. **มือถือเล่นได้จริง แนวนอน** มีจอยสติ๊กเสมือน (ผู้ใช้)

## 3. ไม่อยู่ในขอบเขตรอบนี้ / แผนอนาคต

- **ระดับการแต่งตัวละคร** (ผู้ใช้ให้จดไว้ว่าจะทำในอนาคต):
  - ระดับ 1 — **รอบนี้ทำ**: เลือกตัวละครสำเร็จรูป + เปลี่ยนสี
  - ระดับ 2 — อนาคต: ประกอบเองแยกชิ้น (หัว / ผม / ชุด / สี) พร้อมหน้าแต่งตัวละคร
  - ระดับ 3 — อนาคต: ของแต่งที่ปลดล็อกหรือได้จากอีเวนต์
  - ที่เก็บค่าตัวละครต้องออกแบบเผื่อระดับ 2–3 (§8)
- ไม่ทำ i18n ไทย/อังกฤษในงานนี้ (แผนแยกที่มีอยู่แล้ว) แต่ข้อความ UI ใหม่ต้องไม่ฝังตายจนแปลยาก และฟอนต์ต้องแสดงภาษาไทยได้
- ไม่เปลี่ยนระบบ WebRTC, แชท, listings/orders, events ฝั่งเซิร์ฟเวอร์ — เปลี่ยนแค่ชั้นแสดงผลกับวิธีเปิดหน้าต่าง
- ไม่ให้เจ้าของร้านวาดหรือจัดผังร้านเอง (ยังคงหลักการ "template + parameters" ใน README)
- ไม่ทำหน้าแต่งตัวละครแบบเต็ม (ระดับ 2)

## 4. ข้อห้าม (anti-goals)

- **ห้ามใช้อาร์ต โมเดล ภาพ เสียง หรือของใดๆ จาก Shadowverse / Cygames โดยเด็ดขาด** เอามาแค่ "ฟีล" (ผู้ใช้)
- ห้ามใช้ asset ที่สัญญาอนุญาตไม่ชัดเจน หรือห้ามใช้เชิงพาณิชย์ (§7)
- ห้ามสร้างโลโก้หรือแบรนด์ใหม่ (PRODUCT.md: ยังไม่มีโลโก้ ห้ามคิดขึ้นเอง)
- ห้ามกลับไปเป็นแบบ "ทุกแผงเปิดค้างพร้อมกัน" ซึ่งเป็นต้นเหตุของปัญหาเดิม

## 5. โหมดเดินในร้าน vs โหมดนั่งโต๊ะ

### โหมดเดินในร้าน
- ฉาก 3D เต็มจอ ไม่มีแผงแชทเบียดถาวร
- กล้องมุมบุคคลที่สาม ตามหลังตัวละคร มองลงมาจากมุมสูงเล็กน้อย (Claude — เดาจาก "ฟีล Worlds Beyond" ผู้ใช้ไม่ได้ค้าน)
- คอมพิวเตอร์ใช้ WASD / ลูกศรเดินเหมือนเดิม (คงพฤติกรรมเดิมที่ไม่จับคีย์ตอนพิมพ์ในช่องข้อความ ดูคอมเมนต์ใน ShopScene.js) มือถือใช้จอยสติ๊กเสมือนมุมซ้ายล่าง
- ป้ายชื่อลอยเหนือหัวตัวละครทุกตัว

### โหมดนั่งโต๊ะ — แบบ "C1" (ผู้ใช้เลือกจาก mockup)
เพราะผู้เล่นจะเปิดกล้องส่องสนามการ์ดตอนเล่น **ตรงกลางจอจึงเป็นภาพกล้องจอใหญ่จอเดียว** (ผู้ใช้)

- เข้าโหมดนี้โดยกดปุ่ม "เข้าร่วม" เมื่ออยู่ใกล้โต๊ะ (ดู §10) แล้วกล้องจะเคลื่อนเข้าไปที่โต๊ะ ยังเห็นขอบโต๊ะ 3D ด้านล่างให้รู้สึกว่านั่งอยู่จริง
- **จอใหญ่**: ค่าเริ่มต้นเป็นกล้องของคู่แข่ง หรือคนอื่นที่เปิดกล้องอยู่คนแรกที่ไม่ใช่ตัวเรา ถ้ายังไม่มีใครเปิดกล้อง ให้แสดงสถานะว่าง (Claude)
- **จอเล็ก**: ตัวเรากับคนอื่นที่เปิดกล้อง เรียงด้านข้างหรือด้านล่าง **กดจอเล็กเพื่อสลับขึ้นจอใหญ่** (ผู้ใช้)
- แชทโต๊ะอยู่ด้านขวา ปุ่มไมค์ / ลำโพง / กล้อง (พร้อมเลือกอุปกรณ์แบบ split-button เดิม) อยู่ด้านล่าง มีปุ่ม "ลุกจากโต๊ะ"
- **แชทร้านถูกซ่อน**ระหว่างนั่งโต๊ะ ปุ่มแชทร้านยังแสดงตัวเลขข้อความใหม่ กดเปิดดูได้ (Claude — ผู้ใช้ไม่ได้ตอบตรงๆ ปรับได้ภายหลัง)
- ใช้ขีดจำกัดเดิม: voice ≤10, video ≤4 ต่อโต๊ะ
- ต้องเคารพ `prefers-reduced-motion`: ถ้าเปิดไว้ ให้ตัดภาพทันทีแทนการเคลื่อนกล้อง

## 6. HUD และเมนู (ผู้ใช้เลือก "แบบ 2")

- มุมขวาบนมี 2 ปุ่ม:
  - **💬 แชทร้าน** เป็นปุ่มแยก มีตัวเลขแดงบอกจำนวนข้อความที่ยังไม่อ่าน กดแล้วเปิดแผงแชทร้าน
  - **⊞ เมนู** กดแล้วเด้งเป็นตาราง 3×3: ร้านค้า (listings), อีเวนต์, เด็ค, ตั้งค่า, ออกจากร้าน ช่องที่เหลือว่างไว้ใช้ในอนาคต
    (ช่องอื่นนอกจากร้านค้ากับอีเวนต์ Claude เลือกจากฟีเจอร์ที่มีอยู่แล้ว) ช่องว่างไม่ต้องแสดงก็ได้ ตารางต้องเพิ่มช่องได้ง่าย
- ร้านค้ากับอีเวนต์เปิดได้ทั้งจากเมนูและจากการเดินไปที่เคาน์เตอร์หรือบอร์ด → ทั้งสองทางต้องเปิดแผงเดียวกัน
- การเดินไปที่เคาน์เตอร์หรือบอร์ด: เมื่อเข้ารัศมีให้ขึ้นปุ่ม "เปิดร้านค้า" / "ดูอีเวนต์" ให้กด ไม่เปิดเองอัตโนมัติ เพื่อไม่ให้เด้งใส่คนที่แค่เดินผ่าน (Claude)
- แผงที่เปิดจาก HUD เปิดได้ทีละแผง และต้องปิดได้ชัดเจน

## 7. หน้าตาและ asset

- สไตล์การ์ตูน สีสด low-poly / toon ไม่เน้นแสงเงาสมจริง (Claude ตีความจากฟีลที่ผู้ใช้ต้องการ)
- **ใช้โมเดลฟรีที่ใช้เชิงพาณิชย์ได้ไปก่อน** (ผู้ใช้) Claude เลือกให้ใช้เฉพาะ **CC0** เช่น Kenney, Quaternius, KayKit
  เพื่อตัดปัญหาเรื่องเครดิตและสิทธิ์
- ต้องบันทึกที่มาและสัญญาอนุญาตของ asset ทุกชิ้นไว้ในไฟล์เดียว เช่น `client/public/models/CREDITS.md`
  เผื่อวันหลังเปลี่ยนเป็นงานที่จ้างทำ
- ของที่ต้องมี: ตัวละคร 8–12 แบบที่มีท่าเดินและท่ายืน, โต๊ะ, เก้าอี้, เคาน์เตอร์, บอร์ดประกาศ,
  ชั้นวางหรือตู้โชว์การ์ดสำหรับตกแต่ง, พื้น และผนัง
- **ธีมร้าน** (`server/src/scenes/themes.js`: default/sunset/forest/ocean/midnight) ใช้กำหนดสีผนัง พื้น
  และเฟอร์นิเจอร์ฝั่ง client (Claude)

## 8. ตัวละคร (ระดับ 1)

- ผู้เล่นเลือกตัวละครจากชุดสำเร็จรูป และเลือกสีหลักได้ (ผู้ใช้เลือกระดับ 1)
- ตอนนี้สีถูกสุ่มให้ตอนเข้าร้าน (`AVATAR_COLORS` ใน `server/src/rooms.js`) และไม่ได้เก็บไว้
  ต้องเปลี่ยนเป็น**เก็บค่าตัวละครถาวรใน `users`** โดยเพิ่ม migration ใหม่ (ห้ามแก้ migration เก่า)
- รูปแบบที่เก็บ: Claude แนะนำ `avatar_config JSONB` เช่น `{"v":1,"character":"kenney-04","color":"#e5484d"}`
  เพื่อให้เพิ่มชิ้นส่วนระดับ 2 ได้โดยไม่ต้องเปลี่ยน schema อีก
- ผู้เล่นที่ยังไม่ได้เลือก: ใช้ตัวละครเริ่มต้นกับสีที่สุ่มแบบเดิม
- ที่เลือกตัวละคร: ในหน้าตั้งค่า (`ui/settings.js`) เป็นตัวเลือกง่ายๆ มีภาพตัวอย่าง (Claude)
- รูปโปรไฟล์ (`avatar_url`) ไม่ได้ใส่บนตัวละครแล้ว แต่ยังใช้ในแชท และใส่ในป้ายชื่อได้ (Claude)
- ต้องส่งค่าตัวละครไปกับข้อมูลผู้เล่นใน `join-shop` และตอนมีคนเข้าร้าน เพื่อให้ทุกคนเห็นตัวละครของกันและกัน

## 9. มือถือ (แนวนอน)

- **บังคับแนวนอน** (ผู้ใช้) ถ้าถือแนวตั้งให้ขึ้นข้อความให้หมุนจอ (Claude)
- ฉากเต็มจอ ใช้ HUD ตาม §6 จอยสติ๊กเสมือนมุมซ้ายล่าง ปุ่มต้องใหญ่พอให้นิ้วกด
- ตอนนั่งโต๊ะ: กล้องจอใหญ่อยู่ซ้าย แชทโต๊ะอยู่ขวา จอเล็กอยู่ใต้จอใหญ่ ปุ่มควบคุมอยู่ล่างขวา (ตาม mockup)
- ตอนพิมพ์แชทแล้วคีย์บอร์ดบังจอ ยอมให้บังชั่วคราวได้ เพราะส่วนใหญ่ตอนเล่นจะคุยเสียงกัน (Claude) แต่ช่องพิมพ์ต้องยังมองเห็น
- เรื่องประสิทธิภาพ: ต้องลื่นบนมือถือ Android ระดับกลาง ให้จำกัดจำนวนโพลีกอน ใช้ texture atlas หรือ material ร่วมกัน
  เปิด shadow แบบถูกๆ หรือไม่เปิดเลย และจำกัด pixel ratio (Claude)

## 10. ส่วน "how" ที่ตัดสินใจแล้ว

- **Three.js** แทน Phaser สำหรับฉากร้าน (Claude — ใช้กับ Vite + vanilla JS เดิมได้ ไม่ต้องเพิ่มเฟรมเวิร์ก UI)
  ส่วน UI อื่นยังเป็น DOM ซ้อนบน canvas เหมือนเดิม
- **เซิร์ฟเวอร์ยังเป็นเจ้าของข้อมูลเหมือนเดิม** ตำแหน่ง `x/y` บนพื้นยังเป็นพิกัดเดิม (floor pixels)
  ฝั่ง client แปลงเป็นระนาบพื้น 3D ด้วยสเกลคงที่ ทำให้ระบบ move, rate limit, proximity และ test เดิมยังใช้ได้ (Claude)
- **ผังร้านยังมาจาก template / scene ฝั่งเซิร์ฟเวอร์** (`templates.js`, `default.js`) ต้อง**เพิ่มตำแหน่งเคาน์เตอร์กับบอร์ด**
  (เช่น `COUNTER: {x,y,radius}`, `BOARD: {x,y,radius}`) ลงในทุก template/scene และใน payload ของ `join-shop`
  และต้องจัดตำแหน่งไม่ให้ทับรัศมีโต๊ะ (Claude)
- **การเข้าโต๊ะเปลี่ยนจาก "เข้ารัศมีแล้วเข้าเอง" เป็น "กดปุ่ม"** (ผู้ใช้):
  - เดินเข้ารัศมีโต๊ะ → ขึ้นปุ่ม **"เข้าร่วม" (Join)** แต่ยังไม่เข้าแชท ยังไม่เข้า call และกล้องยังไม่เปลี่ยน
  - กด "เข้าร่วม" → ส่ง `join-table` (ได้ `tableId` และแชทโต๊ะ) แล้วเข้าโหมดนั่งโต๊ะ C1
    และ**เข้า voice call อัตโนมัติ โดยเปิดไมค์ไว้เลย แต่กล้องยังไม่เปิด** (ผู้ใช้)
  - **ไม่มีเก้าอี้ ไม่มีระบบจองที่นั่ง ไม่มีท่านั่ง** เพราะหนึ่งโต๊ะมีคนอยู่ได้หลายคน (ผู้ใช้) ตัวละครยืนอยู่ตรงที่กดเข้าร่วม
    คนอื่นในร้านเห็นว่าคนนี้อยู่โต๊ะไหนจากวงแหวนหรือป้ายเหนือหัว แบบเดียวกับ `seatRing` เดิม (Claude)
  - ระหว่างอยู่ในโหมดนั่งโต๊ะ ตัวละครเดินไม่ได้ ต้องกด "ออกจากโต๊ะ" ก่อน แล้วระบบจะส่ง `leave-table`
    และกลับไปโหมดเดินในร้าน (Claude)
  - ฝั่งเซิร์ฟเวอร์ต้องตรวจตอน `join-table` ว่าผู้เล่นอยู่ในรัศมีโต๊ะนั้นจริง ถ้าตอนนี้ยังไม่ได้ตรวจก็ต้องเพิ่ม พร้อม test (Claude)
- การชนกับโต๊ะ, การ lerp ตำแหน่งผู้เล่นอื่น และ throttle การส่ง move (50ms) ให้คงพฤติกรรมเดิมไว้

## 11. ปล่อยให้ผู้ลงมือตัดสินใจ

- โครงไฟล์ฝั่ง client (เช่น แยก `scene3d/` เป็นโมดูลย่อย), วิธีโหลด GLTF, การทำ instancing
- รายละเอียดแสง สี มุมกล้องที่แน่นอน และ easing ของกล้อง
- เลือก asset pack ตัวไหน ขอแค่เป็น CC0 และสไตล์เข้ากัน
- จะลบ Phaser ออกจาก dependency หรือไม่ ถ้าไม่มีส่วนอื่นใช้แล้ว
- รายละเอียดการ์ดแสดงอีเวนต์บนบอร์ด 3D (เช่น ป้ายบนบอร์ดแสดงจำนวนอีเวนต์ที่กำลังจะมา) — มีก็ดี ไม่บังคับ

## 12. คำตัดสินเพิ่มเติมหลังผู้ตรวจอ่าน (Claude ทั้งหมด ค้านได้)

- **จอใหญ่เริ่มต้น**: ระบบยังไม่รู้ว่าใครเป็น "คู่แข่ง" (โต๊ะไม่มีที่นั่ง และ pairing ของอีเวนต์ไม่ได้ผูกกับโต๊ะ)
  รอบนี้ใช้ "คนอื่นที่เปิดกล้องคนแรก" แล้วกดสลับเอง ส่วนการผูกกับ pairing ของอีเวนต์เก็บไว้เป็นแผนอนาคต
- **แถบบนเดิม** (แจ้งเตือน, Orders, My Shop, Events, ออกจากระบบ): ซ่อนตอนอยู่ในร้าน ย้ายกระดิ่งแจ้งเตือน
  (มีตัวเลข) ไปเป็นปุ่มบน HUD ข้างปุ่มแชทร้าน ส่วน Orders กับ My Shop (เฉพาะเจ้าของร้าน) ย้ายไปอยู่ในตาราง ⊞
- **แผงจากเมนู**: ร้านค้า, อีเวนต์, Orders, เด็ค และตั้งค่า เปิดเป็นแผงซ้อนบนฉาก 3D ตัวละครยังอยู่ในร้าน
  และ call ยังไม่หลุด ถ้าหน้าไหนใหญ่เกินจะทำเป็นแผง (เช่น My Shop) ให้ใช้ปุ่ม "ออกจากร้าน" แล้วไปหน้านั้นตามปกติ
  ส่วน `.dashboard-shell` ของ events/decks ให้นำมาแสดงในแผงซ้อนแทนการเปลี่ยน route ขณะอยู่ในร้าน
- **ผังร้าน**: ไม่ย้ายโต๊ะเดิม ให้ขยายพื้นเพิ่มเป็นแถบตามผนังด้านบนสำหรับเคาน์เตอร์กับบอร์ด ทำแบบนี้ทุก template และ scene
  ทุกร้านมีเคาน์เตอร์ ถ้าไม่มีสินค้าให้แสดง "ยังไม่มีสินค้า" ตามหลัก Honest UI
- **เป้าประสิทธิภาพ**: ≥30 fps บน Android ระดับกลาง เมื่อมีผู้เล่นในร้านพร้อมกัน 30 คน (ตามประมาณการใน CLAUDE.md)
  เดสก์ท็อปตั้งเป้า 60 fps
- สถานะของข้อที่ระบุว่า "(Claude)" ทั้งหมด: ใช้เป็นค่าเริ่มต้นได้ ผู้ใช้จะทดลองแล้วปรับภายหลัง

## 13. ข้อกำหนดของโปรเจกต์ที่ต้องทำตาม (จาก CLAUDE.md)

- ฝั่งเซิร์ฟเวอร์ที่เปลี่ยน: ต้องรัน `npm run test:all` และเพิ่มหรือปรับ test ด้วย
- client: รัน `npm run build` และ `node --check` กับไฟล์ JS ที่แก้
- migration ใหม่ต้องรันกับ DB ทิ้งได้ก่อน ห้ามแก้ migration ที่รันไปแล้ว
- แผงใหม่ที่เปิดเต็มจอต้องเพิ่มเข้า hide-list ของทุกหน้า (`main.js`, `ownerDashboard.js`, `adminPanel.js`)
- ใช้ `confirmDialog()` / `<dialog>` แทน `window.confirm`
- อย่าสมมติว่ามีแค่เกม Vanguard เกมเดียว
- ใช้ชื่อ VobbLiX เท่านั้น
