# อีเวนต์ ส่วนที่ 3: ประวัติการแข่งของผู้เล่น — เอกสารออกแบบ

วันที่: 2026-10-22 · สถานะ: ผู้ใช้อนุมัติแล้ว

"(ผู้ใช้)" = ผู้ใช้ตัดสินเอง · "(Claude)" = Claude ตัดสินแทน ผู้ใช้ค้านได้

## 1. เจตนา

พองานจบ ผู้เล่นอยากย้อนดูว่างานนั้นตัวเองแข่งไปอย่างไร **แต่ละรอบเจอใคร แพ้หรือชนะ และจบอันดับที่เท่าไหร่** (ผู้ใช้)
ตอนนี้ข้อมูลพวกนี้อยู่ในระบบครบแล้ว (`tournament_matches`, `tournament_players.final_rank/final_label`)
แต่ไม่มีหน้าไหนรวมไว้ให้ผู้เล่นดูย้อนหลัง หน้าวันงานของส่วนที่ 1 แสดงเฉพาะรอบปัจจุบันกับตารางคะแนน

ในแวนการ์ด D Standard ผู้ใช้อยากให้ประวัติบอก **เกรด 3 ในไรด์ไลน์ของคู่แข่ง** ด้วย
แต่ข้อมูลนี้ต้องมาจากเด็คที่ผู้เล่นส่งเข้าอีเวนต์ ซึ่งอยู่ในส่วนที่ 4 ส่วนที่ 3 **จึงยังไม่ทำเรื่องนี้ ให้รอส่วนที่ 4** (ผู้ใช้)
ทั้งข้อมูลจาก server และหน้าจอต้องเผื่อที่ให้ส่วนที่ 4 เติมได้โดยไม่ต้องรื้อ (Claude, §6)

## 2. เป้าหมาย

1. ในเมนู topbar มีปุ่ม **"Match history"** อยู่ข้าง "My deck" กดแล้วเปิดหน้าประวัติ (ผู้ใช้)
2. หน้าประวัติเป็นรายการอีเวนต์ที่ผู้เล่นเคยแข่ง **เรียงจากงานล่าสุด** แต่ละแถวบอก ชื่องาน, ร้าน, วันที่, เกม และอันดับที่ได้ (ผู้ใช้)
3. กดที่งานไหนก็ **กางผลรอบต่อรอบ** ออกมา: รอบ (Swiss ก่อน แล้วต่อด้วย top cut), ชื่อคู่แข่ง, ผล (ชนะ/แพ้/เสมอ/แพ้ทั้งคู่/บาย) (ผู้ใช้; เสมอ แพ้ทั้งคู่ และบาย = Claude เพราะระบบมีผลแบบนี้อยู่แล้ว)
4. **เห็นแค่เจ้าตัว** ไม่มีทางดูประวัติของคนอื่น ทั้งใน UI และ API (ผู้ใช้)

## 3. ไม่อยู่ในขอบเขต

- เกรด 3 ของคู่แข่งและของตัวเอง → ส่วนที่ 4 (ผู้ใช้)
- ดูประวัติของผู้เล่นคนอื่น, โปรไฟล์สาธารณะ (ผู้ใช้: เห็นแค่เจ้าตัว)
- สถิติรวมข้ามงาน เช่น win rate ทั้งหมด หรือสถิติแยกตามเด็ค (Claude: ผู้ใช้ไม่ได้ขอ ส่วนที่ 4 มีสถิติเด็คอยู่แล้ว)
- ตารางคะแนนทั้งงานหรือ bracket เต็มของงานที่จบไปแล้ว ประวัติแสดงเฉพาะแมตช์ของเจ้าตัว (Claude)
- งานที่ยังแข่งอยู่ ใช้หน้าวันงานของส่วนที่ 1 ต่อไป (Claude: บอกผู้ใช้แล้ว ไม่ได้ค้าน)
- ไม่มี migration ใหม่ ใช้ข้อมูลที่มีอยู่ทั้งหมด (Claude)

## 4. งานไหนบ้างที่อยู่ในประวัติ (Claude)

แถวของผู้เล่นใน `tournament_players` ที่ **ลงแข่งจริง** คือ `entry_status = 'entered'`, `no_show = false`
และ **มีแมตช์อย่างน้อยหนึ่งแมตช์** ในงานนั้น (รวมบาย) และงานนั้น `status = 'completed'`

เงื่อนไข "มีแมตช์" จำเป็น: คนที่ถอนตัวก่อนงานเริ่ม (`POST /:id/drop` ตอนเปิดรับสมัครหรือ check-in)
หรือโดนตัดสิทธิ์ตอน check-in ยังมีแถว `entered` + `no_show = false` + `dropped = true` อยู่ ระบบไม่ได้เก็บเวลาที่ drop
จึงใช้ "มีแมตช์" เป็นตัวบอกว่าได้เล่นจริง งานเก่าก่อน migration 020 ก็ใช้กฎเดียวกัน

- งานที่ถูกยกเลิก (`cancelled`) ไม่แสดง แม้จะแข่งไปบางรอบแล้ว เพราะไม่มีผลสุดท้าย
- คนที่อยู่ใน waitlist, ไม่ได้รับเลือกจาก lottery หรือไม่มาแข่ง (no-show) ไม่มีงานนั้นในประวัติ เพราะไม่ได้เล่นเลย
- คนที่ถอนตัวก่อนงานเริ่ม ไม่มีงานนั้นในประวัติ (ไม่มีแมตช์)
- คนที่ drop กลางทาง (รวมถึงโดนตัดสิทธิ์ ซึ่งระบบทำเป็นการ drop) **ยังมีงานนั้นในประวัติ** แสดงแมตช์ที่เล่นไปแล้ว
- เรียงตาม `completed_at` ใหม่สุดก่อน วันที่ที่แสดงในแถวคือ `starts_at` ถ้ามี ไม่มีก็ใช้ `started_at`

ไม่ทำแบ่งหน้าในรอบนี้ ผู้เล่นคนหนึ่งไม่น่าจะมีงานเกินหลักร้อยในช่วงแรก (Claude) ถ้าทำง่าย ให้ server จำกัดไว้ 200 งานล่าสุด

## 5. อันดับที่แสดง (Claude)

ใช้ `final_rank` และ `final_label` ที่ระบบตั้งไว้ตอนจบงาน

- มี `final_label`: แสดงเป็นป้าย `Champion`, `Runner-up`, `Top 4`, `Top 8`, ... (ใช้ `PLACEMENT_LABELS` ใน `client/src/ui/events/common.js` ร่วมกัน)
- มีแค่ `final_rank`: แสดง `#N of M` โดย M = จำนวนผู้ที่ลงแข่งจริงในงานนั้น (นิยามเดียวกับ §4 คือมีแมตช์อย่างน้อยหนึ่งแมตช์)
  - M นับคนที่ drop ระหว่าง Swiss ด้วยแม้คนเหล่านั้นจะไม่มีอันดับ คนอันดับสุดท้ายจึงอาจเป็น `#10 of 12` ได้ ตั้งใจให้หมายถึง "จากทุกคนที่ลงแข่ง"
- ไม่มีทั้งสองอย่าง (คนที่ drop ระหว่าง Swiss ตามกติกาตอนนี้ไม่มีอันดับสุดท้าย): แสดง `Dropped after round N`
  - N คือรอบ Swiss สุดท้ายที่ผู้เล่นคนนั้นมีแมตช์ เพราะตารางไม่ได้เก็บว่า drop รอบไหน
  - ถ้าโดนตัดสิทธิ์ (มีบทลงโทษ `disqualification` สถานะ `confirmed`) แสดง `Disqualified` แทน `Dropped`
- คนที่ drop หรือโดนตัดสิทธิ์ระหว่าง **top cut** แพ้แมตช์นั้นไปและได้ `final_rank`/`final_label` ตามปกติ (`advanceFromBracket`)
  ให้แสดงอันดับนั้นตามปกติ และถ้าโดนตัดสิทธิ์ให้ **มีป้าย `Disqualified` ต่อท้ายอันดับ** ด้วย (ผู้ใช้)
  ป้ายนี้ใช้กับทุกกรณีที่มี `disqualification` สถานะ `confirmed`
- ในแถวรายการงานให้แสดงสถิติ W-L-D สั้น ๆ ข้างอันดับด้วย เช่น `3-1-0` (Claude) นับบายเป็นชนะ นับแพ้ทั้งคู่เป็นแพ้

## 6. ผลรอบต่อรอบ

แต่ละแมตช์ของเจ้าตัวในงานนั้น เรียง Swiss รอบ 1..n แล้วต่อด้วย top cut รอบ 1..m

| ช่อง | ที่มา |
|---|---|
| รอบ | `Round N` สำหรับ Swiss; top cut ใช้ชื่อรอบตามขนาด bracket (`Top 8`, `Semifinal`, `Final`) ตอนนี้ยังไม่มีฟังก์ชันชื่อรอบ (`placementLabel` ใน `tournament/bracket.js` คืนค่าเป็นอันดับ ไม่ใช่ชื่อรอบ) ให้เขียนใหม่: รอบสุดท้าย = `Final`, ก่อนหน้า = `Semifinal`, ที่เหลือ = `Top N` ตามจำนวนคนในรอบนั้น (Claude) |
| คู่แข่ง | `display_name` ของคู่แข่ง; บายแสดง `Bye`; บัญชีที่ถูกลบแล้วแสดง `Deleted player` (Claude) |
| ผล | มองจากฝั่งเจ้าตัว: `Win` / `Loss` / `Draw` / `Double loss` / `Bye`; ถ้าแมตช์ไม่มี `result` (ไม่ควรเกิดในงานที่จบแล้ว) แสดง `No result` |
| บทลงโทษ | ถ้าบทลงโทษของเจ้าตัวผูกกับแมตช์นั้น แสดงระดับ + เหตุผลใต้แมตช์ (§7) |

**ช่องสำหรับส่วนที่ 4 (Claude):** แต่ละแมตช์ใน API มีฟิลด์ `opponentDeck: null` ไว้ก่อน
ส่วนที่ 4 จะเติมเป็นข้อมูลไรด์ไลน์ (เช่นชื่อการ์ดเกรด 3) เฉพาะงานแวนการ์ด D Standard
หน้าจอแสดงคอลัมน์นี้ **เฉพาะเมื่อมีค่า** ตอนนี้จึงไม่มีคอลัมน์ว่างให้เห็น

## 7. บทลงโทษในประวัติ (Claude, ตามเอกสารส่วนที่ 1)

เอกสารส่วนที่ 1 เขียนไว้ว่า "ผู้ถูกลงโทษ ผู้จัด และกรรมการเห็น; ส่วนที่ 3 จะแสดงในประวัติ"
ประวัติเห็นแค่เจ้าตัวอยู่แล้ว จึงแสดงบทลงโทษของเจ้าตัวได้

- ระดับใช้ `PENALTY_LABELS` ใน `client/src/ui/events/common.js`
- บทลงโทษ match loss เขียนทับ `result` ของแมตช์อยู่แล้ว ผลในประวัติจึงเป็น `Loss` ถูกต้องเอง
- แสดงเฉพาะสถานะ `recorded` และ `confirmed` ไม่แสดง `pending` หรือ `rejected` (งานจบแล้ว pending ที่ค้างไม่มีผล)
- บทลงโทษที่ผูกกับแมตช์แสดงใต้แมตช์นั้น ที่ไม่ผูก (`match_id` เป็น null) แสดงรวมไว้ท้ายรายละเอียดงาน

## 8. Server

### 8.1 `GET /events/history` (ต้อง login)

อยู่ใน `server/src/routes/tournaments.js` และต้อง **ลงทะเบียนก่อน `/:id`** แบบเดียวกับ `/upcoming`
ไม่รับ user id จากภายนอก ใช้ `req.auth.userId` เท่านั้น ข้อนี้คือสิ่งที่ทำให้ "เห็นแค่เจ้าตัว" จริง (ผู้ใช้ §2.4)

ส่งรายการงานพร้อมแมตช์ทั้งหมดในครั้งเดียว (Claude: ข้อมูลเล็ก ไม่ต้องยิงซ้ำตอนกางรายละเอียด)

```json
{
  "events": [{
    "eventId": "…", "name": "…", "game": "vanguard",
    "vanguardRegion": "th", "vanguardRegulation": "d_standard",
    "shopName": "…", "shopCode": "…",
    "date": "2026-10-20T10:00:00.000Z",
    "players": 24,
    "finalRank": 5, "finalLabel": "top8",
    "dropped": false, "dropRound": null, "disqualified": false,
    "record": { "wins": 4, "losses": 1, "draws": 0 },
    "matches": [{
      "phase": "swiss", "round": 1, "roundLabel": "Round 1",
      "opponentName": "…", "result": "win",
      "opponentDeck": null,
      "penalties": [{ "level": "warning", "reason": "…" }]
    }],
    "otherPenalties": []
  }]
}
```

ชื่อฟิลด์เปลี่ยนได้ตามสไตล์ของโค้ด ขอแค่มีข้อมูลครบตามนี้และ **ไม่ส่ง user id หรือข้อมูลส่วนตัวของคู่แข่ง** นอกจากชื่อที่แสดง

### 8.2 Query

ฟังก์ชันใหม่ใน `server/src/db/tournaments.js` (เช่น `listMatchHistory(userId)`)
ใช้ query จำนวนคงที่ ไม่ทำ query ต่องาน (ไม่ใช่ N+1): ดึงแถวผู้เล่น + งาน + ร้าน, ดึงแมตช์ทั้งหมดของแถวผู้เล่นเหล่านั้นพร้อมชื่อคู่แข่ง, ดึงบทลงโทษ แล้วประกอบใน JS
การแปลง `result` เป็นมุมมองของเจ้าตัว, การนับ W-L-D, การหา `dropRound` และชื่อรอบ ให้แยกเป็นฟังก์ชันบริสุทธิ์ (เช่นใน `server/src/tournament/history.js`) เพื่อเขียน unit test ได้

## 9. Client

- ปุ่มเมนู `topbar-menu-history` ใน `client/index.html` ต่อจาก `topbar-menu-mydeck` ไอคอน Lucide (เช่น `history`) ผ่าน `ui/icons.js`
- route ใหม่ `/history` ใน `main.js` (idempotent re-render ตามกฎ router)
- โมดูลใหม่ `client/src/ui/matchHistory.js` ใช้ layout `.dashboard-shell` ตามกฎของโปรเจกต์ และต้องเพิ่ม `#match-history` (หรือชื่อที่ใช้) ใน hide-list ทุกที่ (`main.js`, `ownerDashboard.js`, `adminPanel.js`)
  - ไม่จำเป็นต้องมี sidebar หลายหัวข้อ ถ้า `.dashboard-shell` บังคับให้มี ใช้หัวข้อเดียวก็ได้ (builder ตัดสิน)
- รายการงาน: แต่ละงานเป็นแถวที่กางได้ (`<details>`/`<summary>` หรือปุ่ม `aria-expanded`) แสดงชื่องาน, ร้าน, วันที่, ป้ายเกม (`GAME_LABELS`), อันดับ, W-L-D
- รายละเอียดที่กาง: ตารางหรือรายการแมตช์ตาม §6, บทลงโทษตาม §7, และลิงก์ "View event" ไป `/events/:eventId`
- สถานะว่าง: "No finished events yet" พร้อมลิงก์ไปหาอีเวนต์ในล็อบบี้; สถานะกำลังโหลดและโหลดไม่สำเร็จแบบเดียวกับ `lobbyEvents.js`
- ข้อความเป็นภาษาอังกฤษไปก่อน (ยังไม่มี i18n) และเคารพ `prefers-reduced-motion` ถ้ามีแอนิเมชันตอนกาง

หน้าตาไม่ใช่ดีไซน์สุดท้าย เน้นใช้งานได้ครบและอ่านง่ายบนมือถือ (Claude)

## 10. เทสต์และการตรวจ

- Unit (`server/test/unit/`): ฟังก์ชันบริสุทธิ์ใน §8.2 — ผลจากมุม player1/player2, บาย, draw/double loss, นับ W-L-D, `dropRound`, ชื่อรอบ top cut
- Integration (`server/test/integration/`):
  - งาน Swiss-only ที่จบแล้ว: ประวัติมีงาน มีทุกแมตช์ อันดับตรงกับ `final_rank`
  - งาน swiss_cut: แมตช์ top cut ต่อท้าย Swiss และป้าย `final_label` ถูก
  - คนที่ drop: มีงาน แมตช์ที่เล่นไปแล้ว และ `dropRound` ถูก
  - งานที่ยกเลิก, waitlist, no-show, คนที่ถอนตัวก่อนงานเริ่ม และงานที่ยังไม่จบ ไม่อยู่ในประวัติ
  - คนที่โดนตัดสิทธิ์ใน top cut: มีอันดับตามปกติ และ `disqualified: true`
  - คนที่โดนตัดสิทธิ์ระหว่าง Swiss: ไม่มีอันดับ และ `disqualified: true`
  - ผู้เล่น A เรียก API แล้วไม่เห็นงานของ B (ไม่มีช่องให้ระบุ user) และเรียกโดยไม่ login ได้ 401
  - บทลงโทษ pending/rejected ไม่แสดง
- `npm run test:all` ใน server, `npm run build` ใน client, `node --check` ไฟล์ JS ที่แตะ
- คลิกทดสอบจริงด้วย `user1@test.local` หลังจบงานทดสอบหนึ่งงาน
